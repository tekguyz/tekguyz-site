# Tooling and build guards

Moved out of `CLAUDE.md` on 2026-09-21 (Job 4). Text is unchanged.

- **`bun run lint` works — keep it working.** `eslint.config.mjs` imports `eslint-config-next`'s **native flat config** directly; it is not FlatCompat-loadable. Note what it cannot buy you: everything in the cascade section above is invisible to a JS/JSX linter. Those rules remain the only thing catching it.
- **`scripts/audit-mobile.ts` does not run under Bun, ever.** `playwright-core` + Bun on Windows fails on both transports — the default `--remote-debugging-pipe` (inherited fds) times out at 180s with the browser visibly spawned, and `connectOverCDP`'s WebSocket fails too. Under Node it works first time. Verified 2026-08-12: the binary is fine, CDP over a TCP port is fine, and disabling the sandbox changes nothing. **Use `bun run audit:mobile <phase>`** — that script entry exists precisely so the wrong invocation isn't the easy one, because the knowledge used to live only in a comment at the top of a 1,900-line file and a session burned turns rediscovering it. Needs a server: `AUDIT_BASE=http://localhost:3000` against `next dev`, or the documented `next start -p 3210`.
- **`bun run check:design` gates `prebuild`.** It asserts that every token **`docs/TOKENS.md`** prints in a fenced `--token: value;` block actually matches `app/globals.css` — **40 of them** across TOKENS.md's five `##` sections: Colour, Type, Radius/container/spacing, Motion, Density. A mismatch fails the build and names the token and both values. **This is the mechanism that makes TOKENS.md quotable**: a value it prints in those blocks cannot silently drift. ~~It reads DESIGN.md, 24 tokens across §2.1/§3.1/§6.1/§8.0.~~ **Both halves were stale** — the source moved to `TOKENS.md` at the 2026-08-12 split, and Colour joined the guard after this line was written, which is where **14** of the 40 come from (~~15~~ — that figure was never right; counted directly 2026-08-28). Re-measured 2026-08-28; the script prints its own count, so read that rather than any number in a doc. Adding a section is still a two-line change in `scripts/check-design.ts` (`TOKEN_SECTIONS`). It cannot check prose, and does not pretend to.
- **`bun run check:claude` catches THIS file going stale, and is deliberately NOT in `prebuild`.** `CLAUDE.md` gets attached to a separate Claude.ai planning Project that cannot see this repo, so a stale copy is read there as current — and nothing updates this file automatically. `scripts/check-claude-md.ts` measures only the **countable** claims: the test count, both token counts, `.vercelignore`'s contents, the honeypot name, every `bun run <script>` named here, and every repo path named in backticks. **It found four wrong on its first run**, including this file's own token count and a `concierge-bus.ts` path missing its `components/` prefix. Not a `prebuild` gate on purpose — a wrong token value ships a visual defect and must block a deploy; a stale sentence in a doc must not. **A pattern that stops matching is reported as a FAILURE, not skipped**, because a check that silently passes when its target gets reworded is the exact failure this repo keeps re-learning. It cannot check the rules themselves — those are decisions, not measurements.
- **~~`.vercelignore` excludes `docs/`~~ — it does not, any more. Measured 2026-08-28: the file holds `scripts/verify.ts` and `scripts/audit.ts`, nothing else.** The incident below is real history and the discipline survives it, so read the rest as *why the rule exists*, not as current state. `bun run check:claude` now watches this exact claim, which is how the drift was caught. **When `.vercelignore` did exclude `docs/` while `prebuild` read `docs/TOKENS.md`**, it broke production for ~4 minutes on 2026-08-12 the first time both were true at once (`docs/archive/HISTORY.md`, "Incident 2026-08-12" — moved out of `docs/STATUS.md` on 2026-09-01): `.vercelignore` predated `check:design`'s dependency on the file by six days, and `bun run build` passing locally proved nothing, because `.vercelignore` only governs what Vercel's checkout receives — a local build reads `docs/` straight off disk regardless. **`.vercelignore` is now a second surface to check before adding anything `prebuild` reads**, not just `app/globals.css` and the file itself. If `prebuild` grows a new file dependency, confirm that path isn't ignored — don't rely on a green local build to prove it.
