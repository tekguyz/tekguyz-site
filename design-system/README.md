# design-system/

The source for the **TEKGUYZ design system artifact**: the thing Claude reads
when it builds a deck, a mockup or a styled page, so that output uses this
brand's real colours, type, spacing and words instead of generic defaults.

Published (private) at https://claude.ai/artifact/SaKW3veCEf5mjbCWjt4pwF

**This folder is not part of the site build.** Nothing in `app/`, `components/`
or `prebuild` reads it. It is here so the design system lives in git rather than
in one Claude account, and so either laptop, and either Claude account, can
publish its own copy from the same files.

## Layout

`project/` mirrors the artifact's own file tree exactly. Publishing is one call
with `root` set to this folder.

| Path | What |
| --- | --- |
| `project/design-system.json` | the index: title, asset records, last change |
| `project/README.md` | the brand book, the first thing any agent reads |
| `project/voice.md`, `solutions.md`, `motion.md`, `media.md`, `platforms.md`, `cascade.md` | further brand-book sections |
| `project/tokens.json` | every colour, type style, space, radius, shadow, duration and easing |
| `project/components/bundle.js`, `bundle.css`, `index.d.ts` | 19 real React components, their stylesheet and prop types |
| `project/components/<Name>/` | a rules page and a live preview per component; `Cover/` is the cover |
| `project/assets/Logos`, `Social`, `Motion` | marks, covers, share image, loops and brand video |
| `project/fonts/` | Geist (one variable file) and two Geist Mono weights |

## Source of truth for the numbers

**`app/globals.css` is the source of truth. `project/tokens.json` is a copy.**

`docs/TOKENS.md` is held to `app/globals.css` by `bun run check:design` on every
`prebuild`. **`project/tokens.json` is not held to anything**, and neither is
`project/components/bundle.css`. Nothing will tell you when they drift.

So: change a token in `app/globals.css`, and update `tokens.json` in the same
commit. Logos and pictures come from `tekguyz-one/brand/media/build`, never by
hand. Copy comes from `tekguyz-one/brand/playbook.md`.

## Publishing an update

Read the artifact's own instructions before publishing. The shapes and caps
live on the artifact, not here:

1. Read `SKILL.md` and `artifact-type/reference/format.md` on the artifact url.
2. Edit the files under `project/`.
3. Publish in one call: `root` = this folder, `file_path` = the absolute path of
   `project/design-system.json`, `files` = every other `project/...` path
   except the uploads below. Send `project/components/index.d.ts` with
   `contentType: "text/plain"`.

The logos, social images, GIFs and videos are **uploaded assets**, not published
files. Their ids are recorded in `project/design-system.json` under
`assetGroups`. The copies under `project/assets/` are the masters kept in git.
Re-upload them only if a file changes, then update the ids.

## Starting a second copy from another account

A second Claude account cannot see the artifact above. It publishes its own:
create one from the Design System artifact type with a title and no files,
upload the files under `project/assets/` (everything that is not a `.md`), put
the new ids in `design-system.json`, then publish this folder to the url that
comes back. Same source, same result.

## Running the components

The components are plain React 18, written without a build step. They read
`window.React`, so there is no bundler to run. Load `tokens.css` (generated by the
artifact page from `tokens.json`), `bundle.css`, React 18, then `bundle.js`.
`project/platforms.md` has a working snippet.
